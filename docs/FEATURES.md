# Adobe Acrobat 機能解析と実装ロードマップ

最終更新: 2026-10-02

このドキュメントは Adobe Acrobat（Reader / Standard / Pro / Studio）の機能を洗い出し、
本プロジェクト（Windows ネイティブの Acrobat クローン）での **優先度・難易度・実装フェーズ** を定めたものです。
技術的な設計は [ARCHITECTURE.md](ARCHITECTURE.md) を参照してください。

---

## 1. 調査の前提

### 1.1 Acrobat のエディション構成（2026 年 10 月時点）

| エディション | 主な対象 | 機能範囲 |
|---|---|---|
| **Acrobat Reader**（無料） | 閲覧者 | 閲覧・印刷・注釈・入力と署名・AI アシスタント（有料アドオン） |
| **Acrobat Standard** | 個人・小規模 | Reader ＋ PDF 編集・作成・変換・ページ整理・結合・フォーム作成・パスワード保護・電子サイン依頼 |
| **Acrobat Pro** | 専門職・法人 | Standard ＋ OCR・墨消し・ファイル比較・ベイツ番号・印刷工程・アクセシビリティ・リッチメディア・アクションウィザード |
| **Acrobat Studio** | 法人・クリエイティブ | Pro ＋ PDF Spaces・AI アシスタント・Adobe Express 連携 |

### 1.2 最近の主な追加機能（2025〜2026）

- **AI アシスタント**: 文書への質問、ワンクリック要約、引用（ページへのリンク）付き回答
- **PDF Spaces**: 複数の PDF・Office・Web ページをまとめて AI で横断分析・共同作業
- **生成プレゼン / インタラクティブレポート / ダッシュボード**: 文書から資料を生成
- **ポッドキャスト・音声要約**: 文書を音声コンテンツに変換
- **会話型 PDF 編集**: 自然言語でテキストの書き換え・置換・書式適用・ハイライト管理
- **Stylize**: 平文書を Adobe Express テンプレートで整形
- **Knowledge Base / Analyzer**: 大量文書からの情報抽出（法人向け）
- **Student Spaces**: フラッシュカード・クイズ・学習ガイドの生成

### 1.3 表の凡例

- **版**: R = Reader, S = Standard, P = Pro, St = Studio（AI）
- **優先度**: ◎ 必須（コア機能） / ○ 重要 / △ 任意・後回し
- **難易度**: ★（易）〜 ★★★★★（難）
- **Ph**: 実装フェーズ（[3. 実装順序](#3-実装順序フェーズ) を参照）

## 3. 実装順序（フェーズ）

### 3.1 順序の決め方

1. **依存関係**: 描画基盤 → 保存パイプライン → 注釈の編集基盤 → それを再利用する署名・編集・墨消し、の順に積み上げる
2. **利用頻度**: 閲覧・注釈・入力と署名・ページ整理・結合・変換・圧縮が最も使われる
3. **技術リスクの早期検証**: PDFium の P/Invoke、保存パイプライン、日本語フォント埋め込みを早いフェーズで確かめる
4. **Windows 標準機能の活用**: OCR・読み上げ・スキャナ・証明書は OS の API で実現できるため、追加の依存なしで実装できる

Phase 0〜4 で **MVP（Reader 相当＋ページ整理・結合）**、Phase 5〜9 で **Standard / Pro 相当**、Phase 10 以降で **Pro の高度機能・AI・配布** を目指します。

### 3.3 各フェーズの完了条件

- **Phase 0**: `dotnet build` が通る。アプリが起動してホーム画面が出る。PDF（パスワード付き含む）を開いて 1 ページ目が表示される。
- **Phase 1**: 1,000 ページ超の PDF を快適にスクロールできる。ズーム・表示モード・サムネイル・しおり・検索・テキストコピー・リンク・印刷が動く。
- **Phase 2**: ページ操作がすべて元に戻せる。結合・分割・抽出した PDF が Acrobat / Edge で正しく開ける。
- **Phase 3**: 作成した注釈が Acrobat / Edge でも同じ見た目で表示・編集できる（日本語を含む）。
- **Phase 4**: 公的書式（AcroForm）に日本語で入力・署名して保存でき、他ソフトでも表示される。
- **Phase 5 以降**: 各機能ごとに、出力した PDF が他ソフトで正しく開けることを自動テストと目視で確認する。

## 4. 対象外・代替とする機能

| 機能 | 理由 | 代替・方針 |
|---|---|---|
| Adobe Document Cloud・Acrobat Sign のサーバー機能 | Adobe のクラウド基盤に依存 | ローカル保存＋同期フォルダ。必要なら自前サーバーを Phase 14 以降で検討 |
| XFA フォーム（動的フォーム） | PDFium の XFA ビルドが必要で仕様も廃止方向 | 表示のみ対応を検討 |
| PDF 内 JavaScript の実行 | V8 組み込みビルドが必要・セキュリティリスク | 計算・書式は組み込み機能で代替（FRM-05） |
| 3D・リッチメディア | 利用頻度が低く実装コストが大きい | 対象外 |
| プリフライト（印刷工程） | 専門性が高い | 対象外（トンボ・出力プレビューのみ検討） |
| Adobe Express 連携・Firefly | Adobe 固有サービス | AI フェーズで Claude API による生成機能として代替 |
